- `batch_create_runner` setup is staged as a testable runner request: it renders the C filtering/progress lines, selected problem clause/formula counts, answer-query extra option, fixed-buffer process name, executable/options, CPU limit, and selected-count metadata after `StructFOFSpecGetProblem`.
- `BatchProcessProblem` orchestration is staged over injected runner spawn/poll hooks, including problem insertion, default filter lookup, max-core strategy launch, C child CPU-slice arithmetic, success/GaveUp status output, optional destination-output and socket-output mirroring, interactive proof-output echoing, and backtracking after each problem attempt.

Parent-side variant execution uses the C variant/prover tables, emits the C-shaped variant batch completion line, and launches a hidden Rust child mode for each concrete variant problem so child stdout can be captured through the generic-process bridge.
