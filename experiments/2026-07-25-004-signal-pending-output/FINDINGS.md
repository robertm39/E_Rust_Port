# Experiment 305: Signal-time pending output

## Status

Complete and accepted for Bead `E_Rust_Port-j76.5.3`.

## Question

Can the Linux hard-CPU-limit trampoline preserve the bytes still pending in
Rust's C-compatible stdout buffer, so `SWB008+1.p` matches C's final output
order without changing ordinary buffering or cooperative timeout behavior?

## Baseline

- Accepted source: `10af55947ff80c677147413cfe9645442465973a`.
- Full Linode run: `.artifacts/linode/260725-181459-0a58`.
- Both C and Rust exit `8` with `ResourceOut` for `SWB008+1.p`.
- C stdout contains the direct failure/SZS banner followed by the previously
  buffered preprocessing, configuration, search-class, and presaturation
  lines.
- Rust stdout contains only the direct failure/SZS banner.

## Diagnosis

C's signal handler writes the failure banner directly to `GlobalOutFD`, calls
`Error()`, and reaches libc `exit()`. The exit path then flushes the pending
`FILE *` stdout buffer, producing the observed direct-before-pending order.

Rust emulates that `FILE *` buffer with a private 8-KiB `Vec<u8>`.
The Linux signal trampoline writes the direct banner and calls libc `exit()`,
which cannot see the Rust-owned pending bytes and does not run Rust `Drop`.

## Candidate

Mirror the committed portion of the private 8-KiB buffer into fixed,
lock-free atomic storage:

- publish bytes before publishing their committed length;
- clear the committed length whenever the ordinary buffer is flushed;
- after the hard-timeout diagnostic, copy the committed snapshot to
  `GlobalOutFD` in fixed stack chunks before libc `exit()`;
- avoid allocation, locks, Rust references into concurrently interrupted
  mutable storage, or any non-signal-safe library operation in the trampoline.

The mirror is output-path-only. It does not change buffer capacity, flush
boundaries, proof-search control flow, or the generated byte sequence during a
normal return.

## Acceptance

- Focused unit tests cover append, capacity, publication, snapshot, and clear.
- Native Linux `SWB008+1.p` matches the C exit, SZS result, and normalized
  stdout under the maintained 60-second hard limit.
- The comprehensive Linode gates pass and the maintained main matrix reports
  zero unexpected mismatches.

the pending preprocessing, configuration, search-class, and presaturation

## Decision

Accept. The candidate closes the last maintained main-prover mismatch with an
allocation-free, race-free signal boundary and negligible measured overhead.
It preserves normal return bytes and flush points, restores C's hard-exit
buffer order, and leaves the separate support-tool and whole-port performance
work visible rather than declaring the overall port complete.
