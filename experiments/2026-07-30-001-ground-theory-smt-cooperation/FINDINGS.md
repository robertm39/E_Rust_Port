# Cooperative ground-theory SMT checking: findings

Bead: `E_Rust_Port-9jt.5.7`

## Question and decision

Can a proof-aware, ground-only SMT layer prune inconsistent typed arithmetic
branches while keeping every accepted step independently replayable, bounding
failure behavior, and preserving a zero-dependency fallback?

Yes for the frozen synthetic difference-logic protocol; not yet for production
Umlaut search. Both a persistent external Z3 process and an experiment-only
Rust C API driver passed every correctness gate, replayed all 96 eligible
decisions per backend, pruned 28 held-out branches, and closed four held-out
all-inconsistent workloads. Their held-out p95 call latencies were 1.71 ms and
0.47 ms, respectively.

Production remains unchanged. The corpus is synthetic rather than a captured
prover branch stream, and the measured backend artifacts are large relative to
Umlaut's current package: 37,152,512 bytes for the self-contained Z3 process or
41,672,304 bytes for `libz3.so` plus the standalone FFI prototype. Follow-up
`E_Rust_Port-9jt.5.10` owns a real/production-like branch evaluation and a
comparison against a small native replayable checker.

## Frozen setup

The tracked `corpus.json` is generated byte-for-byte by `build_corpus.py`. It
contains 30 workloads and 114 branches split equally across train, validation,
and test. Each partition contains integer and real all-inconsistent, mixed,
all-feasible, neutral, and unsupported-general-linear families. Cycle sizes
increase from 4 to 8 to 16 variables without candidate-driven selection.

The trusted fragment is typed ground difference logic:

```text
x - y <= c
```

where either endpoint may be zero, `c` is exact rational, and integer bounds
are integral. A workload asserts its base once and checks branches under
`push`/`pop`. General linear controls are sent to Z3 but are outside replay and
must remain `Unknown`.

The three variants were:

1. no SMT, which returns `Unknown`;
2. one shell-free persistent `z3 -in -smt2` process; and
3. one reference-counted Z3 context used through an experiment-only Rust C API
   driver.

Each Z3 variant used a 5,000 ms timeout, deterministic seeds, models, and
unsatisfiable cores. The process used SMT-LIB named assertions. The C API used
Boolean tracker assumptions and `Z3_solver_check_assumptions`, matching Z3's
documented C API mechanism. Five measured repetitions followed one warm-up.

Z3 source commit
`2d48fd119ce5074b880944c2b1c59e537c99cd46` was transferred as a 6,830,870-byte
Git archive with SHA-256
`9b78c0cc9f330dab9f39c132aba39c92fdba2dbc0aac26dd07b3946592dd21d8`.
The ignored MIT-licensed reference was configured on Ubuntu 24.04 with:


The final run used normal-profile runner
`e-rust-codex-260730-150843-c143` (Linode `101783954`) with repository snapshot

`01589752bdf68313918a909f84538e993d6b5e15cdb3bd74b981964498628e42`.

`Z3 version 5.0.0 - 64 bit`.

No Z3 implementation code was copied or translated. The experiment declares

## Correctness and proof evidence

All 14 final gates passed:

- both interfaces agreed on every raw status;
- five normalized verdict/core/model hashes were identical within each
  backend;
- both matched every expected eligible verdict;
- exact Python replay validated every eligible result;
- the dependency-free Rust checker replayed all 192 accepted certificates,
  with zero invalid;
- removing a core member, altering a core bound, corrupting a model, and
  flipping a decision all made Rust replay fail;
- both backends rejected all 12 raw unsupported answers per run from the
  trusted stream;
- neutral workloads made no solver call;
- a resource-limited process query returned `unknown`;
- killing the external process produced no counted result and completed in
  2.14 ms after the kill request; and
- `Z3_interrupt` made the C API probe return `unknown` with reason
  `interrupted` in 264.98 ms.

Per backend, Z3 produced 60 raw `sat` and 48 raw `unsat` answers. Exact replay
accepted 54 models and 42 cores; six raw `sat` and six raw `unsat` answers from
the unsupported family became `Unknown`. Thus all 96 eligible decisions passed,
42 branches were pruned, and six all-inconsistent workloads closed.

Across both backends, Rust replay covered 192/216 raw decisions (88.89%) and
192/192 trusted decisions (100%). The 24 uncovered raw answers are precisely
the preregistered unsupported controls, not missing certificates.

Held-out validation plus test, per backend, contained:

| Outcome | Count |
| --- | ---: |
| independently replayed `sat` model | 36 |
| independently replayed `unsat` core / pruned branch | 28 |
| unsupported raw answer rejected to `Unknown` | 8 |
| fully closed all-inconsistent workload | 4 |

The no-SMT baseline returned `Unknown` on all 114 branches, pruned none, and
closed none.

## Timing

Call timing includes the solver check and evidence extraction. It comprises 540
measurements per Z3 backend.

| Variant | Median | p95 | Maximum |
| --- | ---: | ---: | ---: |
| persistent process | 0.531 ms | 1.709 ms | 7.943 ms |
| C API FFI | 0.291 ms | 0.473 ms | 0.683 ms |

The process startup median was 0.380 ms and shutdown median was 3.194 ms. The
standalone FFI driver median was 67.891 ms for the complete 108-call corpus;
that total includes process startup, protocol parsing, and output. The
no-SMT Python traversal median was 0.180 ms for the complete 114-branch corpus
and is not a per-call comparator.

These microbenchmarks establish that incremental cooperation can be cheap for
small difference constraints. They do not measure parsing typed TPTP from the
live prover, clause-search effects, proof publication, or process contention.

The Z3 build tree occupied 238,421,568 bytes. `ldd` showed that the process
executable needs only `libstdc++`, `libm`, `libgcc_s`, `libc`, and the loader;
it does not need the separately built shared library. The FFI driver needs
`libz3.so` plus the same ordinary system libraries. Consequently:

- no SMT remains a zero-byte baseline;
- the external-process runtime candidate is 37,152,512 bytes; and
- the standalone FFI prototype plus shared library is 41,672,304 bytes.

The raw final report conservatively wrote 74,339,712 bytes in its
`process_candidate_bytes` field by adding both mutually exclusive Z3 build
outputs. The tracked runner now records that sum separately as
`combined_z3_build_outputs_bytes` and reports the `ldd`-supported process
runtime size above. No solver, driver, license addition, Cargo dependency, or
notice change is adopted.

The process boundary avoids production unsafe Rust and contains crashes, but
needs executable discovery, framing, termination, and StarExec provisioning.
The FFI boundary is faster and supports direct interruption, but adds a large
shared library, a C++ runtime dependency, ABI/version pinning, and unsafe
lifetime/cancellation obligations. Both must retain an explicit no-SMT path.

## Falsification history

The first live report is deliberately retained rather than discarded. The
process path replayed all eligible cores, but the FFI path used SMT-LIB named
annotations through `Z3_solver_from_string`; `Z3_solver_get_unsat_core` returned
no usable C API core. A faulty aggregate gate then divided by the smaller
trusted-decision set and incorrectly passed when all FFI `unsat` results had
been downgraded to `Unknown`.

The correction:

1. requires independently verified evidence for every eligible raw `sat` or
   `unsat`, not merely 100% of already trusted results;
2. adds a regression test for an eligible raw `unsat` with an empty core; and
3. uses explicit Boolean tracker assumptions for the C API path.

The initial 19,520-byte evidence archive has SHA-256
`6a745830d03bb27eb1b35d677da332a43e0453f17f28ed836f65cd0cf9b5cb7a`.
Its report has SHA-256
`788669b8e62ace550505bb3cce1d6087701e73b4f87cbbbc3877576d0a8ad71c`.
The final run is independent and does not reuse its candidate results.

## Limits

Difference logic is intentionally smaller than Umlaut's typed arithmetic
surface. Exact negative-cycle replay does not validate strict inequalities,
general linear arithmetic, nonlinear terms, mixed sorts, quantifiers,
rounding, division, or solver-specific theory lemmas. Satisfying models and
unsatisfiable cores prove only the asserted ground branch.

The corpus is deterministic and held out by partition, but it is generated,
small, and structurally regular. It cannot establish unique theorem-prover
solves or search reduction. The experiment also measures a standalone Rust
driver rather than the binary-size delta of linking Z3 into Umlaut. These are
the reasons to defer production and require `E_Rust_Port-9jt.5.10`.
